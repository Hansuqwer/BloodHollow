# T-104 — External-review hardening wave (Sep 2026)

## Summary

Critical code review of the shipped M3 world+server surfaced six bugs that
either corrupt state, lose audit data, leave dead slots, or open a
potential crash/exception path. Each fix lands with a regression test and
bumped journal epoch (18 → 19). Fresh gate leg: `logs/t104.bwj`
(10 bots × 4 s, mismatches=0, p99=0.72 ms).

## Findings → patches

| # | Bug | Impact | Fix | File |
|---|---|---|---|---|
| 1 | `tryAnvil` failLaw=1 (destroy) zeroed the weapon slot in place (`wslot->itemId=0`) instead of erasing it | Permanent inventory-slot leak (tombstone `itemId=0` occupied a bag slot until the next chaotic death compact path) | Locate the slot index and `erase()` it; bump karma+event before the erase so no iterator invalidation. | `server/src/world.cpp` tryAnvil |
| 2 | `tradeOffer(e, id, qty)` used `for (auto& [id, q] : ...) { if (id==itemId) { q=qty; return; } }` — structured-binding range-for worked by accident on GCC but the `return` exited the outer function after writing qty *only if the loop was entered on the first iteration*; re-offering the same id appended a second row instead of replacing | Deduce loop double-counted items on revised offers (dupe exploit class) | Replace with explicit index loop over `entry.first/entry.second`; re-send the partner-visible notice on update | `server/src/world.cpp` tradeOffer |
| 3 | `vendorSellJunk` / `fenceSellJunk` / `fenceBuy` computed gold as `value*ratio/100*qty` | (a) per-unit truncation lost gold for low-value junk (b) `value*ratio*qty` could overflow u32 on high-value stackables | Widen all three gold calcs to `std::uint64_t` before multiplying; divide last | `server/src/world.cpp` vendorSellJunk / fenceSellJunk / fenceBuy |
| 4 | Trade audit log was opened with `fopen(tradeLogPath(),"a")` with no `create_directories` on the parent | On a fresh checkout or wiped `var/` dir, `fopen` returned NULL silently → executed swaps left no audit line (ADR-0011 violation) | `std::filesystem::create_directories(parent, ec)` before open; warn to stderr on failure | `server/src/world.cpp` tradeCommit |
| 5 | Cross-zone respawn inserted the player into the home zone's spatial grid at `home.spawnPoint` even though `walker.place(home_)` moved the walker to the bindstone/gallows tile | 1-tick AoI ghost at the lawful spawn for chaotic/wanted players returning from another zone | Insert/move at `home_` (actual placed tile) consistently in both branches | `server/src/world.cpp` respawnTick |
| 6 | `parseInvBlob` used `std::stoul(s)` inside a per-field numeric helper, without try/catch | A crafted/malformed blob with a 30+ digit number raised `std::out_of_range` that propagated up to the session-receive path. (The T-104 try/catch in main.cpp handles most packet exceptions, but `parseInvBlob` is also reachable from the DB login reload path where an uncaught exception terminates the world.) | Replace `std::stoul` with a manual bounded digit accumulator (u64 accumulator, reject on u32 overflow) that returns false instead of throwing | `server/src/world.cpp` parseInvBlob |

## Build/infra fix

- `third_party/CMakeLists.txt`: SQLite download from sqlite.org fails in
  sandboxed/CI environments (TLS handshake blocked). Added a fallback that
  uses a locally vendored `third_party/sqlite-amalgamation/{sqlite3.c,h}`
  when present (this is the same pattern other headless sandboxes use).
  ENet download gets the same "copy from in-tree tarball if present"
  treatment. API compatibility pinned (3.38.x → 3.43.x wire-stable).

  but is the correct math per GDD. Documented here so the balancer sees the
