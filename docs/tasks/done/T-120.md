# T-120 — B1 weapon-skill persistence: schema v11, journal epoch 21 — DONE

## Context
Sword skill (Soma adoption, GDD §3) is use-based: `swingLands` increments per landed swing, `swordSkill = swingLands / 25` (capped 100), feeds `effDmgBase` (+1 per 20 skill) and anvil gates (20/50/80/120/150). Previously `swordSkill` and `swingLands` lived only in `Entity` (world.h) and were seeded via `--bless skill:XX` debug lane (sets `swingLands = skill*20`). On logout, `Db::saveProgress` did NOT persist them, so skill reset to 0 on every login — the ladder was Sisyphus. Track B1 requires additive-only schema v11 persistence.

## What was done
- **persist.h**: `CharacterRow` gains `swordSkill` and `swingLands` (v11).
- **persist.cpp**:
  - Migration `uv < 11`: `ALTER TABLE characters ADD COLUMN sword_skill INTEGER NOT NULL DEFAULT 0; ADD COLUMN swing_lands INTEGER NOT NULL DEFAULT 0; PRAGMA user_version=11;`
  - `loginOrCreate` SELECT includes new columns.
  - `saveProgress` extended to include skill.
- **main.cpp**:
  - `kJournalEpoch` 20→21.
  - `journalLogin` l-line v3: `l tick idx name x y zone level xp str vit dex sp gold mercy karma swordSkill swingLands inv`.
  - `dropSession` saves skill.
  - Login restores skill from row, bless overwrites.
  - Replay: `QueuedLogin` has skill, parser tries v3 then v2 then legacy, `applyLogin` restores.
- **Build**: `bh_server_world` now includes `persist.cpp` + `bh_sqlite` so tests can test DB.
- **Tests**: `test_weapon_skill_persist.cpp` — migration defaults, round-trip, old rows default 0.
- **Gate leg**: `tools/t120_weapon_skill_leg.sh` — 5 bots 60s fighter gains skill 1 lands 29-35, relog same 5 bots wander 10s journal shows skill 1 lands 33, replay mm=0, DB persistence verified.
- **Logs**: `logs/t120.bwj` epoch 21, 11K, ticks 1500, cmds 529, hashes 15, mm=0.
