# T-132 — Siege gates: spawn + breach-by-channel (Phase S, 2a/4)

## Context

S1 (T-131) ships window/registration/holder. Gates must fall before the
Heartstone (S2b) matters. `setAttack` refuses furniture targets, and
routing gates through `killMob` would drag XP/loot/whitening along —
both rejected. Breach-by-channel touches no combat path (zero regression
surface on T-047/T-056, zero draws).

## Scope

- `kWireKindSiegeGate = 75`. `spawnSiegeGates(zone)` on zone-6 load: Outer
  + Inner gates, staging positions relative to the zone spawn (anvil-spawn
  spiral for walkability). kind kMob (furniture convention), hp 300.
  STAGING NOTE (in-code): real map-6 constants + movement-blocking land
  with PR #23's map (filed follow-up); gates are breach objectives here,
  not walls.
- `/breach` → journaled `kBreach` → `World::breach(e)`: gates player /
  alive / registered attacker / battle active / same-zone chebyshev ≤ 2 /
  gate standing → gate.hp -= 10, directed progress line. At 0: despawn +
  chatCh-2 "the <name> lies in splinters!" + `[siege]` printf. No repair
  in MVP (filed follow-up); defenders contest emergently by killing
  breachers. No RNG anywhere.
- 30 attacker-actions per gate (300/10) — judgment call, 2-gate delay
  ≈ minutes with a band, stated for M4 tuning.
- NO epoch bump (proven by re-replaying `t128.bwj` mm=0). NO wire change.

## Acceptance criteria

- Zone-6 load seeds exactly 2 standing gates; breach matrix holds;
  progress math exact; kill despawns + broadcasts; journaled path works.
