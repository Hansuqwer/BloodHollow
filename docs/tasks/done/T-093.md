# T-093 — Tier-1 toll retune: options priced, nothing built (DECISION)

## Context
T-086 proved the Tier-1 toll (skill 20 / 30× Rat Pelt / 120g) exceeds single-leg pilgrim income ~6×, so `anvilTries` reads 0 every leg. Retune is economy design — this card prices the options (T-076 pattern). No code changed, no tests, no epoch impact.

## Option A — Lower the pelt toll 30→10 (keep skill 20, keep 120g)

- Change: `kAuraTiers[0].partQty` 30 → 10 (`shared/content/auras.h`, one literal).
- Consequences: richest pilgrim legs bank ~5 pelts; 10 stays out of single-leg reach (still 2× short) but lands inside a 2-leg banking demo (task 7's shape). Skill 20 remains the true gate — most pilgrims never touch 20 sword in-leg either, so A alone does NOT produce in-soak grafts; it only shortens the multi-leg road.
- Cost: content-sim change → **epoch bump** (13→14) + fresh soak journal + replay line. Small diff (<10 lines + toll pins in `test_gear_churn.cpp`-class tests).
- Pointers: `auras.h:25`, `tryAnvil` parts check (`world.cpp`), pilgrim rite math (`tools/bots/main.cpp:697-735`, unchanged).

## Option B — Keep the toll, declare the rite multi-leg progression

- Change: zero code. Document in GDD §7 (anvil): Tier-1 is a multi-session goal; single-leg `anvilTries=0` is expected telemetry, not an anomaly (close the watch item permanently).
- Consequences: nothing replays, nothing bumps, nothing soaks. Task 7 (multi-leg rite demo) becomes the proof vehicle instead of a retune.
- Cost: one docs edit.

## Recommendation (non-binding)

B, unless the director wants grafting visible inside single soaks — the toll's shape (steep parts, skill-gated) reads as deliberate progression design (RFC 0001 Soma adoption: "earn" language in every fiction line), and A spends an epoch bump without actually unlocking in-soak grafts (skill 20 still binds). If A is picked, do it as its own sprint with the pins above; if the goal is in-soak grafts, the honest lever is skill 20→10 PLUS pelts 30→10 (price on request — bigger design question).
