# T-134 — Siege taxes + vault + holder buff + persist (Phase S, 3/4)

## Context

S2 crowns a holder; MVP demands the economics (taxes, holder buff) and
that the castle remembers its master across reboots. The vault is
tax-only in MVP (pledge-lite vault is tax-only too — spending integrates
in Phase P, filed).

## Scope

- `siege_state` table (id=1 row: holder_id, holder_name, vault_gold,
  crowns, updated): `Db::saveSiege` / `Db::loadSiege` (empty → zeros);
  created unconditionally (IF NOT EXISTS, no user_version change —
  characters ladder untouched). Boot loads into the world; throttled
  save (≥600 ticks between writes) on a dirty flag from `tickServer`.
- Tax: while a holder stands, 5% of every PvE kill-gold award diverts to
  the vault (computed post-Greed/post-moral, silent accrual, no draws).
- Holder buff: holder entity acts at +10% hit&dmg (bless-shaped hooks in
  `effAcc`/`effDmgBase`, holder-id gated).
- Crown completion records holder name, increments crowns, marks dirty.
  `gm siege` directed readout: holder (or "unclaimed"), vault, crowns,
  battle state, band count.
- NO epoch bump (zero draws; `t128.bwj` re-replay proof). NO wire change.

## Acceptance criteria

- Tithe math exact (holder/no-holder); buff pins; reboot round-trip
  (crown → save → load → holder/vault/crowns intact); readout lines;
  save throttle (no write storm on farm ticks).

## Tests required

- `tests/test_siege_taxes.cpp`: tax on/off, buff on/off (incl.
  ex-holder unbuffed), Db round-trip + empty default, boot-load pin,
  crown books holder/crowns/dirty, readout lines, throttle pin.

## Out of scope

- Vault spending (Phase P) · siege bots + M4 (S4) · pledge bands ·
  map-6 constants (PR #23 follow-up) · wire 237.
