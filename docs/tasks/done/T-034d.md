# T-034d — Campaign re-gear trip: walk home when the next gear tier is affordable [DONE 2026-09-06]

## Context

T-034c showed the L4-L5 plateau is a death-tax treadmill whose trigger is a
bot-profile gap: the campaign profile has no proactive re-gear — every shop
branch is gated on `nearTown`, which a campaigner only occupies at leg start
and on death-respawn. Gear acquisition was hitched to dying.

## Change (tools/bots/main.cpp, campaign profile)

- New per-bot state `regearHome` + `regearTrips`.
- In the campaign movement block, before the camp-waypoint walk: if the bot
  can afford the next gear tier and isn't wearing it, it walks to the
  bindstone (`homeX/homeY`) instead of the hunting camp. Once `nearTown`, the
  existing economy block does the actual buy/equip unchanged.
  - `!hasBlade && gold >= 260` → walk home for the Pit Blade.
  - `bladeArmed && !hasArmor && gold >= 120` → walk home for Hide Armor.
- Map 1 only (town lives on map 1); cross-zone legs shop on return.
- `regear` counter added to the SUMMARY line for evidence.

No server/sim/protocol change: this is client-side bot behaviour; movement is
client-predicted and server-validated, so replay stays bit-exact by
construction.

## Gate evidence

- Build warning-free (`-Werror`); `ctest` 2/2.
- Fresh smoke leg `tools/t034d_smoke.sh` (2 campaign bots, 240 s):
  `SUMMARY … regear=2 … maxLevel=3`, replay
  `OK ticks=4841 sessionCmds=791 hashes=193 mismatches=0`. The trip fires and
  the journal round-trips bit-exactly.
