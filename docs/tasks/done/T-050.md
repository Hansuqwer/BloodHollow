# T-050 party core — DONE S13 (2026-09-05)

## Context

Phase-3 spine card: grouping is the era's answer to pack content (leash-16
hounds, gnoll packs) and the M2b-final lever (xparty XP → L8 pacing).
Session-scoped design (no persistence) — parties are of-the-hunt, die at
logout/world restart. All semantics journaled as id-resolved Commands so the
replay runner rebuilds parties exactly.

## Delivered

- **Wire (protocol v237)**: C2S `PartyInvite{name}`=21, `PartyAccept`=22,
  `PartyLeave`=23, `PartyKick{targetId}`=24; S2C roster = inventory-style
  reset+slot burst — `PartyReset{partyId,leaderId,count}`=115
  (`partyId=0` ⇒ clear frame) + `PartyMember{id,name,level,hp,hpMax,zoneId}`=116.
  `kProtocolVersion` auto-derives (200 + 37 messages).
- **World model**: `Entity::partyId`, `World::Party{id,leaderId,members}`,
  `parties_` / `nextPartyId_` / `invites_` (targetId → {expiry, inviterId}).
- **Rules**: players only, both alive, same zone, ≤12 tiles (Chebyshev) at
  invite time; inviter bootstraps a new party if unaffiliated, else must be
  leader; leader-only invite/kick; cap 8 (`kPartyMaxMembers`, M3-era);
  one pending invite per invitee (renew overwrites), dies after 200 ticks
  (10 s); `/accept` consumes the newest; leave/kick share one path;
  leader-leave → eldest member inherits; empty party disbands;
  `despawn()` sweeps membership silently (same join-order semantics — the
  replay-identical property).
- **Server glue**: kId handlers resolve character **name → entityId before
  journaling** (journal stores ids; replay is exact); slash verbs in
  kIdChatSend (`/invite <name>`, `/accept`, `/leave`, `/kick <name>`, unknown
  falls through to say); `partyChanged` events → `pushPartyRoster()` to all
  online members + always the `aboutId` session (covers kick/leave wipe);
  1 Hz roster refresh piggybacked on the stats tick for live hp/level.
- **Latent fix uncovered along the way**: command-path WorldEvents were wiped
  by `tick()`'s `events_.clear()` before `distributeEvents` ever ran (anvil-
  floater-class bug). `tickServer` now drains events after the command phase
  (step 1.5) and again post-tick. Pure push-path change — no state-hash impact.
- **Bots**: campaign profile auto-parties at t0 — even-indexed bot
  `/invite`s its sibling by name, odd-indexed `/accept`s; fires only once the
  sibling's name is known.
