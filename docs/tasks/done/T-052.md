# T-052 client party frame — DONE S13 (2026-09-05)

## Context

The frame players stare at all session. Era layout: a small roster panel on
the left margin, red-capped hp bars, name + level per member — HB-style,
matching the stat panel's chrome.

## Delivered

- **Net (`net_client.{h,cpp}`)**: handlers for `PartyReset` (store
  partyId/leaderId, clear roster; id=0 ⇒ frame hidden) and `PartyMember`
  (append row). State lives on `NetClient` (`partyId`, `partyLeaderId`,
  `party` vector) — renderer reads a plain struct, no extra lifetime rules.
- **Panel (`Game::drawPartyFrame`)**: left margin at (8,110), 150 px wide,
  24 px rows; header "PARTY", one row per member: `*name L<level>`
  (`*` marks the leader; own row tinted era-gold), 134 px hp bar under each
  name (red on dark, same palette as stat panel borders).
- Hidden entirely when `partyId == 0` (frame clears on leave/kick/disband —
  the server always pushes an empty reset to the departed).
- Live hp/level freshness via the server's 1 Hz roster refresh (rides the
  stats tick; zero extra timers).

## Tests

Render/UI chrome is hand-verified on screenshots like every other panel;
the *state* it draws is pinned by T-050's server-side tests (roster push
after every `partyChanged` event, wpdate cadence, wipe-on-depart semantics).
Protocol round-trip coverage comes free from protogen's generated
serialize/deserialize being symmetric (same as inventory reset+slot, which
has shipped since S6).

## Evidence

- Gate leg `logs/s13_party_leg*` runs two partied bots; the client build
  compiles the frame against the v237 protocol.
