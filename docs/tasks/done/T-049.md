# T-049 record-path determinism under load — RESOLVED S20 (2026-09-06)

## Original flake (S10 era)

Cadence-25 hashing under 6-bot soaks intermittently diverged live vs
replay: transient walker-tile slip ~tick 125, sometimes permanent. Control
without anvil behaved identically (pre-existing); replaying one journal
twice was bit-stable (recorder-side lane).

## Diagnosis trail

Read the whole record/replay contract in order:

- Live: `tickServer` increments tick, then processCommand pops **one**
  queued command per session (fair-share), stamps the journal c-line with
  the PROCESS tick, applies via `applyWorldCommand` (the single source of
  truth — S10-era refactor, the likely fix).
- Replay: at tick t, applies every line with stamp <= t in FILE order,
  then world.tick(t). File order == live application order because
  journalCommand runs inside processCommand, pre-application.
- Login (l) and disconnect (d) lines stamp N+1, "effect before the next
  tick"; replay applies them pre-tick N+1. Symmetric.
- Chat/ping are journal-skipped and world-inert (rate-limit state is
  session-local, never hashed). Bless bootstrap has its own b-line sidecar,
  journaled post-application, consumed symmetrically by applyLogin.
- Every world-mutating path was audited: spawn/loot/combat/portal/trade/
  duel/refine/repair/bounty/whitening. Nothing consults wall-clock, pointer
  addresses, or unordered-container iteration for sim outcomes
  (zones_ iteration feeds respawnTick with a fixed key/insertion set; draw
  order stable across live/replay of the same binary).

## Why the S10 flake died

The command path was unified (line 665 "single source of truth (T-049)" —
this card's own remediation from S10) and later sprints hardened the
secondary lanes (mob-cadence seeds, journal epoch markers). The acceptance
protocol below is the canary that would prove the card wrong.

## Acceptance evidence (2026-09-06, epoch 5 build)

- `tools/t49_repro.sh` — 3 CONSECUTIVE 6-bot ×300s soaks at
  BH_HASH_CADENCE=25, each replayed twice:
  - run1: 5561 ticks, 1918 sessionCmds, 222 hashes, **0 mismatches**, reader-stable
  - run2: 6005 ticks, 2317 sessionCmds, 240 hashes, **0 mismatches**, reader-stable
  - run3: 5717 ticks, 2338 sessionCmds, 228 hashes, **0 mismatches**, reader-stable
  (logs/t49_run{1,2,3}.bwj + t49_verdict.log; verdict fail=0).
- Burst semantics pinned in `tests/test_burst_stamp.cpp`:
  mass-apply of a same-tick two-move burst provably diverges from
  fair-share (hash inequality) — i.e., the "stamp-when-processed"
  convention is load-bearing, not decoration; and file-order law holds.
- ctest harness fix: bh_tests gets WORKING_DIRECTORY=${CMAKE_SOURCE_DIR}
  so repo-root-relative asset loads (T-063 zone gate) behave under ctest.

## Standing

If a future sprint touches the command path, the repro harness + the two
in-process pins resurrect the same protocol in one leg. Until then: replay
green is trustworthy currency again.
