# T-049 record-path determinism under load (replay flake) — DONE 2026-09-05

## Root cause (found, proven, fixed)

Dual hand-mirrored command switches: live `processCommand()` (network path)
vs the `--replay-world` loop. They had drifted four ways:

1. **kAttack (the observed flake)**: live clears `e.path` *unconditionally*
   before `setAttack()`; replay called only `setAttack()`, which early-returns
   on a dead/missing target. A bot attacking an already-dead mob cancelled
   its in-flight walk path live but not in replay → one 256-unit Q10 sub-step
   slip (e.g. id 292 at tick 115: live 40960 vs replay 41216) → transient
   1-of-N hash mismatches, re-converging after (dumps at tile granularity
   masked it until Q10 dumps).
2. **kSkill**: live falls back to `attackTarget` when `a==0`; replay passed 0
   verbatim (find(0)==nullptr → no-op).
3. **kUseItem**: live uses `channel`; replay used `q.a` (always 0 from the net
   decoder → latent consumable-slot skew).
4. **kBuy / kTradeItem**: live guards `qty > 0`; replay did not.

## Fix

`server/src/command.h`: single `applyWorldCommand(World&, Entity&, Command&)`
consumed by both sinks. `processCommand()` keeps only shell concerns
(journal, chat, ping); replay rebuilds the exact `Command` from journal
fields (a/b/channel are journaled verbatim) and calls the same function.
Regression guard: any future asymmetry between record and replay is now a
single-file diff, not cross-site archaeology.
