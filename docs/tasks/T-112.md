# T-112 — T-111 epoch follow-up: F4 spawn fill is a semantics change (epoch 19)

## Context

T-111 (PR #8) shipped five critical-review fixes claiming "no journal-epoch
bump — hash fields untouched". That claim was never executed: the authoring
sandbox had no cmake/network. Local verification on 2026-09-12 disproved it —
replaying master's `logs/t107.bwj` (epoch 18) under the T-111 tree fails from
the FIRST checkpoint: 81/81 hash mismatches, entities 196 vs 169. A probe
build with only the `initialMobSpawns` hunk (F4) reverted replays the same
leg perfectly clean (`mismatches=0`, `entities=169`, hash values identical
to master's). Root cause: the pre-T-111 `--n`-on-blocked-roll wrap aborted
whole spawners (a blocked first roll wrapped `n` to UINT32_MAX, the
`n > 40` guard broke out), so F4's bounded re-roll fill changes boot-time
spawn counts AND consumes a different number of RNG draws — the entire
world stream shifts. That is a spawn-semantics change under old journals:
per AGENTS.md it must bump `kJournalEpoch` and ship a fresh gate leg. F1,
F2, F3 and F5 are proven replay-neutral on this leg (the probe kept them
all and still replayed clean).

## Scope

- `kJournalEpoch` 18 → 19 in `server/src/main.cpp`, epoch history line
  extended.
- 3 new pins in `tests/test_t112_spawn_epoch.cpp` holding the new spawn law:
  - F4a: fully-blocked spawner rect terminates (maxTries cap) and places
    nothing;
  - F4b: half-blocked rect still fills `maxAlive`, all on walkable tiles;
  - F4c: single-free-tile rect still fills (bounded re-roll; stacking on the
    one walkable tile is legal).
- Fresh gate leg `logs/t112.bwj` (20 bots × 10 s, campaign profile) recorded
  under epoch 19.
