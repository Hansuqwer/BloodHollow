## 2. Where the wall is now (this is the open problem)

The map-5 traces of both reaching legs tell one story:

```
r19  m3g__01  (3,30)->(5,20)  hp 100%->0%    died 3.4 s after entry
r19  m3g__02  (3,30)->(20,4)  hp  84%->61%   reached the font camp's edge
r19  m3g__03  (5,24)->(5,18)  hp 100%->72%
r20  m3g__01  (3,30)->(6,12)  hp  50%->60%   (min 20%)
r20  m3g__02  (3,30)->(12,8)  hp  89%->100%
r20  m3g__03  (3,30)->(10,9)  hp 100%->0%    died en route
r20  m3g__04  (3,30)->(11,8)  hp 100%->39%
```

The party **arrives on map 5 healthy (84–100% hp)** and is killed crossing
the ~25 tiles from the portal `(3,30)` to the font camp `(22,3)`. Deepest
map-5 x reached in r20: **12** — half the crossing. The Gravemother is seen
(`bossSeen=20`) and casts (curse 2) but is never brought to a fight the
party can finish.

Two structural reasons, both visible in the code:

1. **The map-5 route table has ONE node** — `{22, 3, 0.0, false}`. There is
   no staging across the depths, so the crossing is a single 25-tile walk
   through L18–25 content (roadmap Phase 3: "Drowned Crypt (L18–25)") with a
   L13 party. Map 3 got four nodes and a corridor spine; map 5 got none.
2. **The kiter band is disabled on map 5** (`b.mapId != 1 && b.mapId != 3 &&
   b.mapId != 5`, r8c) — so now that the Gravecaller actually bolts, it
   still walks the route into melee instead of holding the 7–8 band outside
   the boss's bolt range 6.

   staging is now reproducible from a cold sandbox. Disclosed, same

   `logs/m3_gate.bwj`**; copy the leg aside and restore the tracked journal
   afterwards (that is what was done for r18/r19/r20).
